# Resolve MDN Link

The `resolveMdnLink` function returns the MDN page for a built-in type, such as `HTMLElement`, `Intl.NumberFormat`, or `Intl.LocalesArgument`, or `null` when MDN does not document it.

It is server-only: importing it from a client component fails the build, so the link table never reaches the browser.

## Usage

Pass it as `resolveExternalLink` to the types factory so built-in types in type signatures link to MDN:

```ts
import { createTypesFactory } from '@mui/internal-docs-infra/abstractCreateTypes';
import { resolveMdnLink } from '@mui/internal-docs-infra/pipeline/resolveMdnLink';

export const createTypes = createTypesFactory({
  TypesTable,
  TypePre,
  resolveExternalLink: resolveMdnLink,
});
```

Types documented on the page keep their page links, and only the type name is linked. See the [`resolveExternalLink` option](../enhance-code-types/page.mdx#resolveexternallink-option) of `enhanceCodeTypes`.

It can also be called directly:

```ts
resolveMdnLink('HTMLElement');
// 'https://developer.mozilla.org/docs/Web/API/HTMLElement'

resolveMdnLink('Intl.NumberFormatOptions');
// 'https://developer.mozilla.org/docs/Web/JavaScript/Reference/Global_Objects/Intl/NumberFormat/NumberFormat#options'

resolveMdnLink('Button');
// null
```

## Which Types Resolve

Every type declared in TypeScript's lib files that MDN covers resolves:

- **Interfaces and global objects** with an MDN page, such as `HTMLElement`, `PointerEvent`, `Promise`, or `Intl.NumberFormat`, link to that page.
- **Aliases of a built-in type**, such as `WindowProxy`, link to the page of the type they alias.
- **Types that only exist in TypeScript**, such as `Intl.NumberFormatOptions` or `AddEventListenerOptions`, link to the section of the parameter they describe: the `options` parameter of the `Intl.NumberFormat()` constructor, or of `addEventListener()`. When several methods take the type, the one whose name starts the type's name wins, and types used too widely to pick one do not resolve.

### With a Source

When you know where a type is declared, pass it as the second argument. Only types declared in the DOM, JavaScript, or worker lib files resolve:

```ts
resolveMdnLink('Range', { kind: 'lib', files: ['lib.dom.d.ts'] });
// 'https://developer.mozilla.org/docs/Web/API/Range'

resolveMdnLink('Range', { kind: 'package', name: 'some-package' });
// null
```

Without a source, matching is by name, so a package's own `Range` also resolves to the DOM `Range` page. `enhanceCodeTypes` does not pass a source to `resolveExternalLink` yet, so links from type documentation match by name.

## How the Table Is Generated

The links come from a table generated with `pnpm -F @mui/internal-docs-infra generate:mdn-type-links`. Pages come from [`@mdn/browser-compat-data`](https://github.com/mdn/browser-compat-data), and parameter sections from the page sources in [`mdn/content`](https://github.com/mdn/content) at the commit pinned in the generator. Rerun it after bumping `@mdn/browser-compat-data`, `typescript`, or the pinned commit.
