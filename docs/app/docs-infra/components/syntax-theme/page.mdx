# Syntax Theme

A ready-made stylesheet for the `pl-*` and `di-*` token classes produced by [`parseSource`](../../pipeline/parse-source/page.mdx). Import it once to get GitHub-style syntax highlighting in light and dark mode, then override any color through CSS variables.

## Usage

Import the stylesheet once, for example in your root layout:

```tsx
import '@mui/internal-docs-infra/syntaxTheme.css';
```

Every code block rendered by [`CodeHighlighter`](../code-highlighter/page.mdx), and inline code highlighted by [`transformHtmlCodeInline`](../../pipeline/transform-html-code-inline/page.mdx), picks up the colors.

import { DemoSyntaxThemeLightDark } from './demos/light-dark';

<DemoSyntaxThemeLightDark />

## Light and Dark Mode

The colors follow GitHub's Prettylights light and dark palettes. The light palette applies by default, so pages without a dark mode need no setup. Switch palettes with a `data-color-scheme` attribute on any ancestor of the code:

| `data-color-scheme` | Palette                                               |
| :------------------ | :---------------------------------------------------- |
| _(not set)_         | Light                                                 |
| `light`             | Light                                                 |
| `dark`              | Dark                                                  |
| `system`            | Follows the operating system (`prefers-color-scheme`) |

Set it on the root element to theme the whole page, typically from the same state that drives your dark-mode toggle:

```html
<html data-color-scheme="dark"></html>
```

The nearest ancestor wins, so a single block can use the other palette by setting the attribute on a wrapper element. The attribute only switches syntax colors; set the page background and the CSS `color-scheme` property in your own styles.

## Customizing Colors

Colors are CSS custom properties. The rules live in the `docs-infra.syntax` cascade layer and the variables are declared with zero specificity, so any declaration of your own takes precedence. Override a color for each palette you use:

```css
:root {
  --color-docs-infra-syntax-keyword: #8250df;
}

[data-color-scheme='dark'] {
  --color-docs-infra-syntax-keyword: #d2a8ff;
}
```

Set a variable on any element to change the colors of the code inside it only.

### Token Variables

The [`di-*` classes](../../pipeline/parse-source/page.mdx#syntax-token-classes) refine a token's color. Their variables are not declared by default: each falls back to the base variable listed here, so changing a base color also changes the tokens that inherit it. Declare one to style that token on its own.

| Variable                                        | Class     | Falls back to             |
| :---------------------------------------------- | :-------- | :------------------------ |
| `--color-docs-infra-syntax-number`              | `di-num`  | `constant`                |
| `--color-docs-infra-syntax-boolean`             | `di-bool` | `constant`                |
| `--color-docs-infra-syntax-nullish`             | `di-n`    | `comment`                 |
| `--color-docs-infra-syntax-this`                | `di-this` | `keyword`                 |
| `--color-docs-infra-syntax-builtin-type`        | `di-bt`   | `constant`                |
| `--color-docs-infra-syntax-punctuation`         | `di-pu`   | `storage-modifier-import` |
| `--color-docs-infra-syntax-object-property`     | `di-op`   | `constant`                |
| `--color-docs-infra-syntax-property-string`     | `di-ps`   | `constant`                |
| `--color-docs-infra-syntax-template-expression` | `di-te`   | `storage-modifier-import` |
| `--color-docs-infra-syntax-template-delimiter`  | `di-td`   | `storage-modifier-import` |
| `--color-docs-infra-syntax-jsx`                 | `di-jsx`  | `string-regexp`           |
| `--color-docs-infra-syntax-jsx-variable`        | `di-jv`   | `variable`                |
| `--color-docs-infra-syntax-jsx-tag`             | `di-jt`   | `string-regexp`           |
| `--color-docs-infra-syntax-html-tag`            | `di-ht`   | `entity-tag`              |
| `--color-docs-infra-syntax-attr-key`            | `di-ak`   | `constant`                |
| `--color-docs-infra-syntax-attr-equals`         | `di-ae`   | `storage-modifier-import` |
| `--color-docs-infra-syntax-attr-value`          | `di-av`   | `string`                  |
| `--color-docs-infra-syntax-data-attr`           | `di-da`   | `constant`                |
| `--color-docs-infra-syntax-css-property`        | `di-cp`   | `constant`                |
| `--color-docs-infra-syntax-css-value`           | `di-cv`   | `constant`                |

Identifiers in inline code (`code[data-inline] .pl-smi`) inherit the surrounding text color so they read as prose.
