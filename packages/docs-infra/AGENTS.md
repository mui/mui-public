# Docs Infra Instructions

## Architecture

- Preserve the runtime boundaries documented in the [architecture guide](../../docs/app/docs-infra/overview/architecture/page.mdx). Do not import Node.js-only modules into client or isomorphic entry points.
- This package is ESM-only. Do not add CommonJS modules.
- Import React as a namespace: `import * as React from 'react'`.

## Public APIs

- Export each public module through its local `index.ts` and add its subpath to `package.json#exports`.

## Tests

- Use Vitest and colocate tests with the source they cover.
- Use `*.test.ts(x)` for unit tests and `user.spec.ts(x)` or `*.user.spec.ts(x)` for user-scenario integration tests.

## Documentation

- Document public APIs at `docs/app/docs-infra/{category}/{kebab-case-name}/page.mdx`.
- Put standalone demos at `demos/{kebab-case-name}/index.ts`. Keep shared demo modules directly under `demos` only when multiple demos use them.
- Configure generated type documentation in `types.ts`. Do not edit generated `types.md` files or sections marked as autogenerated.
- Follow the [file navigation conventions](../../docs/app/docs-infra/conventions/file-navigation/page.mdx).
- Run `pnpm docs:validate` after changing docs conventions or generated documentation inputs.
